## 📘 What Are **Agile Frameworks**?

Agile itself is a **mindset** or **set of values and principles** (from the Agile Manifesto).  
But to **put Agile into action**, teams use **frameworks** — these are **structured ways** to apply Agile in real projects.

👉 Think of **Agile** as the _philosophy_, and **Agile frameworks** as the _tools or methods_ used to implement that philosophy.

---

## 🧱 Popular Agile Frameworks (with Summary)

Here’s a quick list of **Agile frameworks**, what they do, and when to use them:

| Framework                                     | Key Features                                                                                       | Best For                                     |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| **[[Scrum]]**                                 | Time-boxed sprints, defined roles (Scrum Master, PO), ceremonies like sprint planning/review/retro | Teams with stable features & structure       |
| **[[Kanban]]**                                | Visual board, continuous flow, WIP (Work In Progress) limits                                       | Support or maintenance teams                 |
| **XP (Extreme Programming)**                  | TDD, pair programming, continuous integration, short releases                                      | Dev-heavy projects needing high quality      |
| **Lean**                                      | Focus on eliminating waste, delivering fast                                                        | Projects with a need for optimization        |
| **Crystal**                                   | Lightweight, team-size-based, focuses on people and interactions                                   | Small, flexible teams                        |
| **FDD (Feature Driven Development)**          | Build by features, model-first approach                                                            | Large-scale, feature-rich applications       |
| **DSDM (Dynamic Systems Development Method)** | Fixed time/cost, prioritizes business needs                                                        | Projects with strict timelines               |
| **SAFe (Scaled Agile Framework)**             | Scales Scrum/Kanban across big enterprises, multiple teams                                         | Enterprise-level, large orgs                 |
| **Spotify Model**                             | Tribes, squads, chapters – informal but powerful Agile scaling                                     | Companies focused on innovation and autonomy |
| **Agile Unified Process (AUP)**               | Agile adaptation of the traditional Rational Unified Process (RUP)                                 | Teams transitioning from waterfall to agile  |

## 🔧 1. **Scrum** – _"Work in short cycles (Sprints)"_

🌀 Scrum is the **most popular Agile framework**.  
### 🔑 Key Concepts:
- Timeboxed **Sprints** (1–4 weeks)
- Roles: **Scrum Master**, **Product Owner**, **Team**
- Daily **Standups**
- Meetings: **Sprint Planning**, **Review**, **Retrospective**    

🧪 **Example:**

> Your team works on the “Unsend message” feature. You plan it in Sprint Planning, test it during the sprint, and demo it at Sprint Review.

---

## 🔧 2. **Kanban** – _"Work continuously, no sprints"_

🪄 Kanban focuses on **visualizing work** using a **board**.  
There are no sprints — instead, tasks flow **continuously** through stages like _To Do → In Progress → Testing → Done_.
### 🔑 Key Concepts:
- **Visual board**
- **WIP limits** (Work In Progress)
- Continuous delivery (no sprint cycle)

🧪 **Example:**

> A QA picks up bugs from the board one by one, tests them, and moves to the next — no need to wait for a sprint.

---

## 🔧 3. **XP (Extreme Programming)** – _"Do code & testing with high quality"_

👨‍💻 XP focuses on **engineering best practices** to deliver better quality code.
### 🔑 Key Practices:
- **Test-Driven Development (TDD)**
- **Pair Programming**
- Continuous Integration
- Short releases (like mini sprints)

🧪 **Example:**

> Developers write tests _before_ writing the code (TDD). QA helps in building those test scenarios early on.

---

## 🔧 4. **Lean** – _"Remove waste & deliver faster"_

🍃 Lean comes from manufacturing (Toyota) but is used in software to **optimize processes**.
### 🔑 Key Concepts:
- Eliminate **waste**
- Focus on **value**
- **Faster delivery** with fewer steps

🧪 **Example:**

> QA and Dev use a shared checklist to avoid repeated rework, focusing only on what really needs to be tested.

---

## 🔧 5. **Crystal** – _"Agile but lightweight & team-specific"_

🔮 Crystal is very **flexible** — it adapts based on **team size** and **project criticality**.
### 🔑 Key Concepts:
- No strict rules
- Focus on **people, not process**
- Different “Crystal” types: Crystal Clear (small teams), Crystal Red (larger teams), etc.

🧪 **Example:**

> A 3-person startup team builds features without formal roles but follows Agile values like fast delivery and communication.

---

## 🔧 6. **FDD (Feature Driven Development)** – _"Build features one by one"_

🔧 FDD focuses on **designing and building features** in a **structured way**.
### 🔑 Key Concepts:
- Feature list is the base
- Build by **feature** (not tasks)
- Strong modeling & planning upfront

🧪 **Example:**

> Instead of a sprint, QA tests the full “Voice message playback” feature when Dev completes it.

---

## 🔧 7. **DSDM (Dynamic Systems Development Method)** – _"Fixed time, controlled scope"_

🛠️ DSDM is a **business-focused Agile** framework that controls time and budget strictly.

### 🔑 Key Concepts:
- **Time & budget are fixed**
- Scope is adjusted if needed
- Prioritize features using **MoSCoW**:
    - **M**ust have
    - **S**hould have
    - **C**ould have
    - **W**on’t have

🧪 **Example:**

> QA is told: "You have 2 weeks, test only Must and Should Have stories. Others can wait."

---

## 🔧 8. **SAFe (Scaled Agile Framework)** – _"Agile for big companies"_

🏢 SAFe is used when **multiple Agile teams** need to work together in a **large organization**.
### 🔑 Key Concepts:
- Scales Scrum/Kanban to many teams
- Roles: Product Owner, Scrum Master, Release Train Engineer
- **Program Increments** (like quarterly sprints)

🧪 **Example:**

> You're on Team A working on messaging; other teams handle notifications and groups. SAFe helps align all teams together for a joint release.

---

## 🔧 9. **Spotify Model** – _"Agile with autonomy & innovation"_

🎵 Inspired by how Spotify works. Teams are organized into **Squads, Tribes, Chapters, and Guilds** — all focused on **autonomy and culture**.

### 🔑 Key Concepts:
- **Squads** = Agile teams
- **Tribes** = Collection of squads
- **Chapters** = Skill-based groups (e.g., all QAs)
- Promotes innovation & ownership

🧪 **Example:**

> You're part of the QA Chapter, but you work inside a Messaging Squad building features independently.

---

## 🔧 10. **AUP (Agile Unified Process)** – _"Agile version of Waterfall's RUP"_

🧱 AUP is a lighter, agile version of the **Rational Unified Process (RUP)**.
### 🔑 Key Concepts:
- Iterative, model-driven
- 4 phases: Inception → Elaboration → Construction → Transition
- Suitable for organizations moving from Waterfall

🧪 **Example:**

> A QA team uses AUP where each phase includes test planning, test design, and execution as the app evolves.
